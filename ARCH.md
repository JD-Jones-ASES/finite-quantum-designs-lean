# Architecture and lane protocol (working document; not part of the published repository)

## What this repository proves

In formal-conjectures' vocabulary (OQP 13 and 23, restated verbatim; Apache-2.0, see NOTICE):

- **MUBs.** `HasMUBs d m → m ≤ d + 1` for `d ≥ 2`; `HasMUBs 1 m` for every `m` (sharpness); restriction; the tensor
  bound `hasMUBs_mul`; the factorization corollary `hasMUBs_of_forall_primePow`; `HasMUBs d 3` for `d ≥ 2`; the
  quadratic-phase sum `‖Σ_x ψ(c x² + e x)‖² = q` over an odd-characteristic field; complete sets over every
  odd-characteristic finite field, in every dimension `2ⁿ` (stretch), hence in every prime-power dimension;
  `IsMaxMUBCount (pᵏ) (pᵏ + 1)`; `HasCompleteMUBs d ↔ IsMaxMUBCount d (d + 1)` for `d ≥ 2`; `μ(2) = 3`, `μ(4) = 5`,
  `μ(8) = 9` with explicit kernel-checked tables.
- **SICs.** Gerzon's bound over `ℂ` for any common overlap `c ≠ 1`; sharpness at `c = 1`; the equality case
  `c = 1/(d + 1)` and the frame identity for `d ≥ 2`; every SIC family is a POVM; `HasSICPOVM d ↔` `d²` equiangular
  unit vectors; `card_le_of_sicOverlapSq`; `HasSICPOVM 2`, `3`, `8` (Hoggar).

`Challenge.lean` holds the 14 definitions and 26 pinned theorems, each closed in `Solution.lean` (generated by
`scripts/gen_solution.py`) by the `_internal` theorem of the same name in the modules of `QuantumDesigns/`.
`QuantumDesigns/Defs.lean` restates the definitions character for character (same `import Mathlib`).

## Rules (binding for every lane)

1. Every statement in your module is PINNED: keep its name, hypotheses and conclusion. Add helpers freely in your
   file, prefixed with your lane prefix (`bd_`, `of_`, `tp_`, `sm_`, `ch_`, `tn_`, `gz_`, `hg_`). If a pin is false or
   unprovable as stated, prove the nearest correct version under a new name, leave the pin with `sorry`, and report
   it under `wrong_pins`.
2. Never edit any other file (other modules, `Challenge.lean`, `Solution.lean`, scripts) except to add an import
   line to your own module. If you need a fact from another module that is not pinned there, prove a private copy in
   your file named `aux_…` and report the duplication.
3. Build ONLY with `bash scripts/lane-build.sh QuantumDesigns.<YourModule>` from your worktree root (two
   machine-wide build slots and a free-memory wait; the box has 16 GB and little free). Never run `lake build` or
   `lean` directly, never several targets in one call, never two builds at once. Read the whole output: grep for
   `error` and `sorry` separately; a build that prints "Build completed successfully" with sorry warnings is not done.
4. Kernel-only: no `native_decide`, `axiom`, `unsafe`, `partial`, `implemented_by`, `mutual`, `opaque`, `sorry`
   (except pins still open); `decide +kernel` is allowed. Mathlib v4.35.0-rc2 at `.lake/packages/mathlib`
   (grep it for names; it is a junction, read-only). Known renames: `le_or_lt` is `le_or_gt`, `push_neg` is
   `push Not`? (check), `Set.mem_setOf_eq` is `Set.mem_ofPred_eq`, `if_true/if_false` are `ite_true/ite_false`;
   `omega` has no dark shadow (pick disjuncts first); `section` variable hypotheses need `include`.
5. Commit on your branch as you go (`git add QuantumDesigns/<Module>.lean; git commit -m "..."`); never push;
   scratch files go under your worktree (never `/tmp`, which is shared across lanes).
6. Time box per lane in the brief; then stop and report what is closed. Partial progress with every closed statement
   committed is valuable; do not leave the file in a non-building state at the end.
7. A statement's docstring is published: no lane residue ("Lane:", "TODO"), no owner's name, no "record".
